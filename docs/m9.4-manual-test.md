# M9.4 manual test (limits, disk floor, monitoring, sandbox, hardening report)

Server 0.10.1. Phone-side rows are in `otter-android/docs/m9.4-manual-test.md`. The three-node guide that these rows
assume is `docs/11-deployment.md` §14; the security checklist is §8.

**Only on disposable VMs** (`deploy/test/vm.sh`, named instances `a`/`b`/`c`), never on a real node: the rows below
drop packets, fill the disk and hammer the node port. On real nodes only the read-only rows (marked *read-only*) are
run, and only after the owner said so. "—" = not run yet.

## Automated checks

```bash
export PATH=/usr/lib/go-1.26/bin:$HOME/go/bin:$PATH
nice -n 15 go vet ./...
nice -n 15 go test -p 4 -count=1 ./internal/limits/ ./internal/metrics/ ./internal/service/ ./internal/gateway/ \
  ./internal/replication/ ./internal/config/ ./cmd/otter-node/
# scripts_test writes into dist/: run it in a copy of the tree
T=$(mktemp -d); git ls-files -z | xargs -0 tar -c | tar -x -C "$T"; (cd "$T" && bash deploy/test/scripts_test.sh)
# offline unit scores (systemd 252+ on the PC)
systemd-analyze security --offline=true deploy/templates/otter-node.service | tail -n1     # 1.5
systemd-analyze security --offline=true deploy/templates/otter-backup.service | tail -n1   # 0.5
```

## Three VMs

```bash
OTTER_VM=a OTTER_VM_SSH=2222 OTTER_VM_WSS=27443 deploy/test/vm.sh start
OTTER_VM=b OTTER_VM_SSH=2223 OTTER_VM_WSS=27444 deploy/test/vm.sh start
OTTER_VM=c OTTER_VM_SSH=2224 OTTER_VM_WSS=27445 deploy/test/vm.sh start
```

Then build the network on them with `docs/11-deployment.md` §14 in a scratch admin dir (`OTTER_ADMIN_DIR`,
`OTTER_SSH_OPTS="-i $PWD/.vm/id"`, `--ssh-port` per node, `OTTER_PROBE_ADDR` / `OTTER_SKIP_DNS=1` for the admin-side
checks), or with `deploy/test/e2e-mesh.sh --keep` for two of them.
